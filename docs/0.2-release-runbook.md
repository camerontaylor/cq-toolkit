## Audit the exact package

The operator supplies `FINAL_02_SHA` from the promoted, reviewed `main`
commit and uses a fresh checkout. The shell exits on every failed gate.
Do not run the publication command while any placeholder or gate is open.

```sh
set -euo pipefail
git clone https://github.com/camerontaylor/cq-toolkit.git cq-v020-publish
cd cq-v020-publish
git checkout "$FINAL_02_SHA"
test "$(git status --porcelain)" = ""
test "$(node -p 'require("./package.json").version')" = 0.2.0
grep -qx "export const SERVER_VERSION = '0.2.0';" src/harness/mcp/server.ts
grep -qx "const CLIENT_VERSION = '0.2.0';" src/driver/acp/index.ts
export PNPM_CONFIG_VIRTUAL_STORE_TYPE=project
pnpm install --frozen-lockfile
pnpm run check
pnpm run build
pnpm run denylist
npm whoami --registry https://registry.npmjs.org/
pack_dir="$(mktemp -d)"
pnpm pack --pack-destination "$pack_dir"
pack_file="$pack_dir/camerontaylor-cq-toolkit-0.2.0.tgz"
test -f "$pack_file"
expected_sha256="$(shasum -a 256 "$pack_file" | cut -d' ' -f1)"
echo "sha256 $expected_sha256"
expected_sha1="$(shasum -a 1 "$pack_file" | cut -d' ' -f1)"
echo "sha1 $expected_sha1"
expected_integrity="sha512-$(openssl dgst -sha512 -binary "$pack_file" | openssl base64 -A)"
echo "integrity $expected_integrity"
listing="$pack_dir/listing.txt"
tar -tzf "$pack_file" > "$listing"
cat "$listing"
violations="$(sed 's|^package/||' "$listing" | sed '/^$/d' | grep -vE '^(package\.json|README\.md|LICENSE|dist|policy)(/.*)?$' || true)"
test -z "$violations" || { echo "paths outside the files allowlist: $violations"; exit 1; }
grep -qx 'package/dist/index.js' "$listing"
grep -qx 'package/policy/denylist/patterns.yml' "$listing"
unpack_dir="$(mktemp -d)"
tar -xzf "$pack_file" -C "$unpack_dir"
mkdir -p "$unpack_dir/package/scripts"
cp scripts/denylist-scan scripts/package.json "$unpack_dir/package/scripts/"
(cd "$unpack_dir/package" && DENYLIST_SCAN_NO_DIST_ALLOWLIST=1 ./scripts/denylist-scan)
npm publish --dry-run "$pack_file" --access public --registry https://registry.npmjs.org/
test "$(git status --porcelain)" = ""
```

The `SERVER_VERSION` and `CLIENT_VERSION` checks fail the audit if the MCP
server or ACP client identity was not bumped with `package.json`. The project virtual store keeps
the release build off any shared pnpm store, as in
`.github/workflows/pack-audit.yml`. The listing checks fail on any path
outside the `package.json` `files` allowlist and on a missing entry point or
denylist.

`pnpm run check` here is the release's local macOS full gate, an
owner-run check on the exact promoted SHA. Green required CI on that SHA
remains the full-gate authority
([focused-checks contract](focused-checks-contract.md) §1). The tarball is
packed with `pnpm pack`, as in `.github/workflows/pack-audit.yml`; `npm` is
used only for registry identity, the dry run, the upload of those exact bytes
and the readback.

The unpacked scan above runs the tarball's own `policy/denylist/patterns.yml`
over the shipped bytes with the `dist/` allowlist dropped, mirroring
`.github/workflows/pack-audit.yml`; the repository-tree `pnpm run denylist`
does not cover the packed `dist/`.

Install this
same `pack_file` into a separate empty consumer and exercise the root and
every declared public subpath plus both bins. Retain its output. Record the
Node, pnpm and npm versions, checkout SHA, exact tarball SHA-256, SHA-1 and
SHA-512 integrity, tree listing,
pack-audit result, dry-run exit, and publisher identity. Repack and repeat
all checks after any source or packed-byte change.

## Owner publication and readback

After the owner verifies the preflight record and authorizes publication of
the audited bytes, publish that same tarball from the same checkout:

Re-assert the audited digest immediately before publishing; abort on any
mismatch (`expected_sha256`, `expected_sha1` and `expected_integrity` are the
values recorded during the audit, so re-export them from the preflight record
if the shell was restarted):

```sh
test "$(shasum -a 256 "$pack_file" | cut -d' ' -f1)" = "$expected_sha256" || { echo "tarball changed since audit; aborting"; exit 1; }
npm publish "$pack_file" --access public --registry https://registry.npmjs.org/
npm view @camerontaylor/cq-toolkit@0.2.0 version dist.tarball dist.shasum dist.integrity --registry https://registry.npmjs.org/
test "$(npm view @camerontaylor/cq-toolkit@0.2.0 dist.integrity --registry https://registry.npmjs.org/)" = "$expected_integrity" || { echo "registry integrity differs from the audited tarball"; exit 1; }
test "$(npm view @camerontaylor/cq-toolkit@0.2.0 dist.shasum --registry https://registry.npmjs.org/)" = "$expected_sha1" || { echo "registry shasum differs from the audited tarball"; exit 1; }
```

The registry `dist.integrity` (SHA-512) must equal the audited tarball's
SHA-512 integrity; that is the binding comparison. The `dist.shasum` (SHA-1)
comparison is secondary. Save the registry listing and publish identity. Only then create and push annotated
`v0.2.0` on the verified toolkit source SHA through the reviewed release
procedure; record the remote tag target. No tag is created by this draft.
