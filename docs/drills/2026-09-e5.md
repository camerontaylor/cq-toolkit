## Goal (ws-e acceptance)

End-to-end against a scratch GitHub repo (integration lane, dispatch-gated):
a seeded review thread gets fixed, replied, and resolved by the SHIPPED
`runReviewLoop`; a re-run is a true no-op (zero fix jobs, zero gh
mutations, verify stage never runs). The loop closes with a non-privileged
arbitrary reviewer's thread — the market-gap scenario — riding plain gh
REST/GraphQL (reply + resolve), no admin surface anywhere.

## Deviation record (single identity, recorded)

The drill holds exactly ONE GitHub identity, so the seeded review thread is
created via the REST API under the SAME token identity that authored the PR
— a stand-in reviewer, not a second account. The fixture flag is
`REVIEWER_ROLE_SIMULATED = true`
([test/e2e/helpers/review-live.ts](../../test/e2e/helpers/review-live.ts)),
asserted in the live test, and this paragraph is the human-readable record.

Consequence handled as data: the seeded thread's author IS the responder
(`pr-author`), so the live loop runs with
`classifyConfig: { ...defaultClassifyConfig, skipResponderAuthoredThreads:
false }` — the shipped default would classify the thread `skip`
(`responder_authored`) before any job is planned. This is a per-drill
classifyConfig flip (R3 data), never a code change.

## How to dispatch

```sh
gh workflow run live-review --ref <branch-with-the-workflow> -f run_id=<fresh-id>
gh run watch   # or: gh run list --workflow=live-review
```

Requirements: repo Actions secret `GH_TOKEN` (repo scope, same identity the
drill records); dispatch-only by construction — never fires on push/PR.
The vitest leg runs from source with `LIVE_GH=1`; the precondition step
refuses a misconfigured dispatch loudly instead of reporting green-skipped.

## What the drills caught (the point of the lane)

Nine attempts; the first seven failures are the lane's findings, each fixed
in this PR:

1. Drills 1/3 — REST thread-anchoring traps (I11-class, live): `-f` passes
   strings ("3" is not an integer), and the line+side+subject_type shape
   422s into the wrong oneOf arm; the legacy `position` anchor (typed `-F`)
   is the shape that works. Recorded in the helper's seeding comment.
2. Drill 2 — cross-run coupling: the scratch repo persists, so fixture
   branches became run-scoped (`e5-fixtures-<run_id>-<ts>`).
3. Drills 4–6 — three real loop defects the unit lane could not see:
   GitHub/Codex sticky housekeeping comments classify actionable (fixed:
   `defaultLoopClassifyConfig` skip patterns — GitHub marker sticky, the
   Codex review-summary sticky); a `changed:false` sibling false-positived
   the unreported-commit publish gate (fixed: HEAD-accountability — the tip
   must be a verified claimed commit, not every row's claim); the loop
   answered its own top-level replies forever (fixed: every reply body
   carries the `<!-- cq-review-loop:owner/repo#pr -->` signature and the
   default config skips it — the classify vocabulary's "responder's own
   words" made deterministic under the single-identity deviation).
4. Drill 7 — the test's split dispatch logs defeated the
   already-answered skip (runs must share the log; that IS the idempotency
   mechanism).
