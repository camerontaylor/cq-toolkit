## Goal (ws-e acceptance)

End-to-end against a scratch GitHub repo (integration lane, dispatch-gated):
a seeded review thread gets fixed, replied, and resolved by the SHIPPED
`runReviewLoop`; a re-run is a true no-op (zero fix jobs, zero gh
mutations, verify stage never runs). The loop closes with a non-privileged
arbitrary reviewer's thread — the market-gap scenario — riding plain gh
REST/GraphQL (reply + resolve), no admin surface anywhere.

## Deviation record (single identity, recorded)

The drill holds exactly ONE GitHub identity, so the seeded review thread is
created via the REST API under the SAME token identity that authored the PR
— a stand-in reviewer, not a second account. The fixture flag is
`REVIEWER_ROLE_SIMULATED = true`
([test/e2e/helpers/review-live.ts](../../test/e2e/helpers/review-live.ts)),
asserted in the live test, and this paragraph is the human-readable record.

Consequence handled as data: the seeded thread's author IS the responder
(`pr-author`), so the live loop runs with
`classifyConfig: { ...defaultLoopClassifyConfig,
skipResponderAuthoredThreads: false }` — the shipped default would classify
the thread `skip` (`responder_authored`) before any job is planned. This is
a per-drill classifyConfig flip (R3 data), never a code change; deriving
from the loop default keeps its sticky/self-reply suppression.

## How to dispatch

```sh
gh workflow run live-review --ref <branch-with-the-workflow> -f run_id=<fresh-id>
gh run watch   # or: gh run list --workflow=live-review
```

Requirements: repo Actions secret `GH_TOKEN` (repo scope, same identity the
drill records); dispatch-only by construction — never fires on push/PR.
The vitest leg runs from source with `LIVE_GH=1`; the precondition step
refuses a misconfigured dispatch loudly instead of reporting green-skipped.

## What the drills caught (the point of the lane)

Ten attempts; **attempts 1–8 failed** — each failure is a lane finding,
fixed in this PR — **drill 9 went green on the pre-cycle-1 code**, and
**drill 10, the recorded run, went green on the final code** after
cycle-1 addressing:

1. Drill 1 — REST thread anchoring, first trap (I11-class, live): `-f`
   passes STRINGS (HTTP 422: `"3" is not an integer`); the numerics moved
   to typed `-F`.
2. Drill 2 — cross-run coupling: the scratch repo persists, so the next
   run's fixture-branch push went non-fast-forward; branches became
   run-scoped (`e5-fixtures-<run_id>-<ts>`, one branch + PR per run).
3. Drill 3 — REST thread anchoring, second trap: the typed
   line+side+subject_type shape 422s into the WRONG oneOf arm (line and
   subject_type are forbidden keys on the reply arm); the legacy
   `position` anchor (typed `-F`; position equals the file line for a
   fresh-add hunk) is the shape that works. Both traps are recorded in the
   helper's seeding comment.
4. Drills 4–6 — the first real loop defects the unit lane could not see
   (drill 5's needs-human, drill 6's diagnosis): the GitHub auto-generated
   marker sticky classified actionable (fixed: the first
   `defaultLoopClassifyConfig` pattern), and a `changed:false` sibling
   false-positived the unreported-commit publish gate (fixed:
   HEAD-accountability — the tip must be a verified claimed commit, not
   every row's claim).
5. Drill 7 — the test's split dispatch logs defeated the already-answered
   skip (fixed: both runs share ONE log — that IS the idempotency
   mechanism). Drill 7's diagnostic also read comment 5705054746 as a NEW
   markerless housekeeping shape ("This comment shows the latest
   checks…") and added a bare-text skip pattern for it — a MISREAD of a
   length-truncated body: the comment was the Codex summary all along
   (see 6), and cycle 2 REMOVED the bare-text pattern as author-blind and
   spoofable (a human opening a comment with that phrase would have real
   feedback suppressed); the unit pin now pins the opposite — a
   human-authored bare-text comment must PLAN A JOB.
6. Drill 8 — the last two: the Codex review bot's sticky PR summary
   (`<!-- codex-pull-request-review-summary …`) answered as feedback
   (fixed: the codex-marker skip pattern — the suppression set stays
   generation-signature anchored), and the SELF-REPLY cycle — issue
   comments don't thread, so the loop answered its own top-level replies
   forever (fixed: every reply body LEADS with the
   `<!-- cq-review-loop:owner/repo#pr -->` signature and the default
   config skips bodies opening with it — the classify vocabulary's
   "responder's own words" made deterministic under the single-identity
   deviation).
