# The F5 live merge drill — merge-prs ops end to end (2026-09-16)

Purpose: the ws-f integration acceptance, executed against github.com with the
SHIPPED composition — "a 3-PR stack with one seeded conflict lands via merge
commits only; branch history shows no squash/force" — through
`runMergePrs` (classify → plan → execute → conflict agent → re-plan), the real
`realMergeEffects`, and the real `SubprocessDriver`. The drill lives in
`test/e2e/merge/live.test.ts` (skipped unless `LIVE_GH=1` + `GH_TOKEN`; plain
`npm run test` never fires it).

## How to run

- Locally: `LIVE_GH=1 GH_TOKEN=<token> npx vitest run test/e2e/merge/live.test.ts`.
  The token must be a classic token with the `repo` scope **plus `read:org`**
  (see the deviations table — `gh pr edit` fails without it).
- CI: Actions → **live-merge** → Run workflow (`.github/workflows/live-merge.yml`,
  `workflow_dispatch` only; optional vitest `-t` name filter via the
  `testFilter` input). PROMOTE_TOKEN carries the scopes above.

## Scenario (exact)

1. Scratch repo `camerontaylor/cq-scratch-f5-p3f-<run>` (private, unique per
   run, LEFT IN PLACE — no `delete_repo` scope).
2. Local clone; local identity + a gh-backed credential helper (the token
   rides `GH_TOKEN` at push time, never argv); main seeded with README +
   `seed.txt` (`alpha` / `beta`).
3. `f5-a` rewords `alpha`→`alpha-A` (PR 1 → main). `f5-b` branches from the
   SAME pre-a commit and rewords `alpha`→`alpha-B` (PR 2 → f5-a — the seeded
   conflict; the drill polls its `mergeable_state` to `dirty`).
   `f5-c` adds `c.txt` (PR 3 → f5-b).
4. Candidates are built from real `gh api` pull state (closed pulls included —
   a merged rung anchors the retarget-self rule) plus a synthetic review
   overlay (see deviations).
5. The conflict agent is a scripted POSIX-sh worker run through the real
   `SubprocessDriver` (fake `f5fake` routing route; `MergeConflictDecisionSchema`
   output): in the prepared merge worktree it performs a REAL union resolution
   of PR 2 — fetch f5-a, `merge --no-commit`, three-way union of `seed.txt` via
   `git merge-file --union`, a NORMAL merge commit, `push HEAD:f5-b` — then
   emits the driver-protocol events (`system` init + `result` success carrying
   `structured_output` `{"decision":"acted","summary":"union merge pushed"}`).
6. Up to 8 outer iterations: candidates are refetched live, `runMergePrs` runs,
   every report is logged; the loop stops when all three pulls report merged.

## Deviations (all recorded in the test's module doc)

| deviation                                                                                                                                     | why                                                                                                                                                                                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Synthetic review overlay (single-identity run — a genuine non-author review is impossible), body `lgtm` matching the frozen `allClearPattern` | the brief's prose body would leave the clean PRs on the 10-minute settle row (row 9) — untraversable without sleeps; row 7's review-of-the-last-commit requirement still holds in full: APPROVED, null author (the house rule: null is never the author — external, counts), submitted strictly after the head commit |
| PR 3's overlay gated on PR 2 reporting closed                                                                                                 | pins the drill deterministically to the retarget path (PR 3 is never eligible while PR 2 is open, so it can only land after the retarget, on the trunk); mirrors a reviewer who approves a stack's tail after its parent landed; forge recompute races can delay passes but never change the landing shape            |
| "No squash" read on main's FIRST-PARENT chain                                                                                                 | a full rev-list walk also lists the PR branch commits — they legitimately ride the merge commits as second parents; a squash/rebase/fast-forward landing would put a non-merge commit on the first-parent chain                                                                                                       |
| The scripted agent waits (bounded, in-script) for `refs/pull/2/head` to carry the sha it just pushed before reporting `acted`                 | found live: `refs/pull/N/head` propagates asynchronously, and the resolve op's instantaneous acted-verification read a stale ref, flipping a good `acted` into a false `indeterminate` — a worker reporting acted owes the caller an observable push                                                                  |
| `git symbolic-ref HEAD refs/heads/main` right after the clone                                                                                 | the scratch repo is EMPTY at clone time, so HEAD is unborn and its name is whatever the transport/init default chose — not reliably `main`; pinning it before the first commit keeps every later ref name well-defined                                                                                                |
| `process.env.GH_REPO` aimed at the scratch repo                                                                                               | the effects layer's gh argv (`gh pr merge <n> --merge`, `gh pr edit <n> --base <b>`) carries no repo and spawns without a repo cwd — without `GH_REPO` they would resolve against the toolkit's own repository                                                                                                        |
| Token scope finding: the FA-provided run token lacks `read:org`                                                                               | `gh pr edit`'s GraphQL lookup needs `read:org` on classic tokens; without it every retarget-self action fails (proven live). The drill therefore requires `repo` + `read:org`, and the workflow wires `secrets.PROMOTE_TOKEN`                                                                                         |
| REST spelling of "merged"                                                                                                                     | REST pulls carry no `MERGED` state — `merged:true` + `state:'closed'` is its GraphQL-`MERGED` equivalent                                                                                                                                                                                                              |

## Follow-up finding — stacked-tail stranding (recorded; needs an issue)

With uniform overlay evidence, a same-pass shape exists where the executor
merges the parent onto main BEFORE the stacked child: the plan orders
[merge-parent, merge-child] (parent first — F2's ordering), the parent's merge
closes it, and the child then merges into the parent's branch — which main has
already moved past. The child reports merged, but its content never reaches
the trunk. Observed live on
[cq-scratch-f5-p3f-mu4kw9ls](https://github.com/camerontaylor/cq-scratch-f5-p3f-mu4kw9ls):
run 2 reported `merged=[2,3]` and `c.txt` was absent from main while PR 3
itself showed merged (base still `f5-b`, merged after PR 2 closed). The
gated-overlay deviation above sidesteps the race, but the underlying gap is
real for open-ended stacks. Candidate fixes: withhold the child when its
`basePr` is a same-pass merge root (re-plan next pass — the closed-ancestor
retarget then re-anchors it onto the trunk), or auto-retarget the child
between actions. Surface = planner/executor, both frozen phase-2 files →
follow-up issue, not a drill-slice change.
