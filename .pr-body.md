definitions across 14 `unittest.TestCase` classes. It is the largest test
module in the repository and the slowest file to navigate. This change is a
**pure move** by subject: no test added, removed, renamed or changed.

## Disclosures

1. **Two classes are split across sibling modules under their original class
   name.** `CurrentTest` (76 KB) and `DiscoveryFailureBoundaryTest` (27 KB)
   each exceed the 24 KB limit, so each module declares
   `class CurrentTest(...)` / `class DiscoveryFailureBoundaryTest(...)` with its
   own subset of test methods. The class name and every `Class.method` name are
   unchanged, which keeps the AST multiset identical.
2. **Shared setUp/helpers are plain, non-TestCase mixins.**
   `CurrentFixture` (14 helpers, including `deferred_entry`/`forge_data`, used
   by both the deferred and discovery modules) lives in `test_crq_fixtures.py`.
   `DiscoveryFailureFixture` (10 helpers) lives in
   `test_crq_discovery_wrapper.py` and is imported by
   `test_crq_discovery_storage.py`. The fixtures module defines no
   `TestCase` classes, so unittest discovery does not collect it as a suite.
   All mixin bodies are byte-identical to the original methods.
3. **Five class-level alias lines are the only non-verbatim moved lines.**
   `OversizedIntervalPartitionTest` referenced `RecentKeysetDiscoveryTest`
   directly; that class now lives in `test_crq_recent_discovery.py`, so
   `AFTER`, `BEFORE`, `setUp`, `forge` and `enrolled` read
   `_recent_discovery.RecentKeysetDiscoveryTest.*` via a module alias. The
   alias (rather than a class import) prevents unittest from collecting the
   keyset class a second time from the partition module.
4. **`setUpModule` is imported by every split module** from
   `test_crq_fixtures.py`. The original module installed the fail-closed
   `subprocess.Popen` boundary and failure observer once per module; the split
   preserves that per-module boundary, so each of the 18 modules gets its own
   temp home and `unittest.addModuleCleanup` teardown. The observer is
   idempotent and activates once per process.
5. **New module header/provenance docstrings and imports are new lines**; all
   moved code, including comments and blank-line grouping inside classes, is
   the original text.
6. `apps/crq-python` is not registered in `test/suite-classes.json`; no
   registry change is required or made.
7. **Known follow-up, not fixed here:** `scripts/lib/test-narrow.mjs` maps a
   source module to `test_<module>.py` only. With `test_crq.py` gone, a change
   to `apps/crq-python/crq.py` no longer has an automatic narrow mapping and
   `pnpm test:narrow` refuses it as unbounded; named test files work. This
   matches the earlier Python splits in this lane (`test_merged_reconcile.py`,
   `test_author_quota.py`, ...), and changing the shared runner mapping is
   outside this move's scope.
